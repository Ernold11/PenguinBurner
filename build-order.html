Overlay Build Order

The goal moved: not “look like Steam” but be the reason to uninstall MangoHud. That is achievable, and the order below is different from the one in the strategy note — because it turns out almost none of it needs the risky renderer work first.

branch agent/overlay-ux base upstream/main 3e6083c 10 Sep 2026

00 · The reordering

The renderer is polish, not a prerequisite

The strategy note put the new Vulkan pipeline first, on the assumption that everything else waited on it. Reading the draw path again: it does not. The current clear-rect renderer can already draw anything made of rectangles — at any coordinate, on any number of lines, in any glyph shape, including a frametime bar graph.

What the pipeline actually buys is transparency and antialiased type — not colour, which the existing draw call already takes as an argument. Real, worth having, and the one change that can break a game that works today. So it moves to the end, and four milestones of visible progress land before we take that risk.

03 · Start here

The first session

Small, reversible, and it makes everything after it testable. Roughly an afternoon.

  1. Install the Vulkan headers and run the two native overlay tests. They compile overlay_text.cpp with a plain C++ compiler and need no GPU — the failure was always a missing header package, not the environment.
  2. Confirm the new baseline: the suite should drop from 14 known failures to 12, all of them systemd and packaging.
  3. Take the glyph table first. It is the smallest change with the most obvious result: a generator script, a wider table, one deleted toupper, and the readout stops shouting. Nothing else in the draw path moves.
  4. Then position. Also self-contained — a config key, a parser branch, a combo box, and origin maths in one function. 
python -m pytest tests/test_native_overlay_text_config.py -q
python -m pytest tests/test_overlay_text.py tests/test_overlay_config.py -q
c++ -std=c++17 -I overlay/native/latency_layer/src -fsyntax-only \
    overlay/native/latency_layer/src/overlay_render.cpp

That last line is the fast loop for M1: the glyph and layout work type-checks in a second without building the whole layer.

04 · Parked on purpose

Where we do not chase parity

×OpenGL games. The overlay is a Vulkan layer and the product already says so out loud. DXVK and vkd3d cover the Windows catalogue; native OpenGL-only titles are a shrinking set, and supporting them means a second renderer and a second injection path.
×Battery, network and media-player rows. MangoHud serves handhelds and streamers too. Our user is at a desk with a tuned NVIDIA card.
×Log upload to a comparison site. Someone else’s service, someone else’s privacy question.
×An interactive in-game config panel. Input capture is the line from the strategy note, and it has not moved. Hotkeys plus the desktop app cover it.

Verification split: M0, M2 and M4 are almost entirely testable on the review machine. M1 and M3 have their logic tested here and their pixels only on your desktop. M5 is desktop-only from the first line. Nothing in this plan claims a hardware result that has not been seen on hardware.
